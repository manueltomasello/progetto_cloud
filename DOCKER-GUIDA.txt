## PASSO 1 — Aggiungi "start" al package.json del backend

Apri backend/package.json e assicurati che ci sia lo script "start":

  "scripts": {
    "dev": "nodemon server.js",   ← quello che usi ora
    "start": "node server.js"     ← AGGIUNGI QUESTO per Docker
  }

Se il tuo file di avvio non si chiama server.js, sostituiscilo col nome corretto
(es. app.js, index.js).


## PASSO 2 — Esporta il database da SSMS

1. Apri SQL Server Management Studio
2. Tasto destro sul database → Tasks → Generate Scripts
3. Scegli "Script entire database and all database objects"
4. In "Set Scripting Options" → Advanced → Types of data to script → "Schema and data"
5. Salva come file: database/init.sql
6. Apri init.sql e in CIMA al file aggiungi queste righe:

   USE master;
   GO
   CREATE DATABASE GestionaleManutenzioni;   ← usa il tuo nome DB
   GO
   USE GestionaleManutenzioni;
   GO

   (poi segue tutto il resto dello script)


## PASSO 3 — Aggiorna le variabili d'ambiente nel backend

Nel codice Node, la connessione al DB deve leggere da process.env.
Esempio con mssql/tedious:

  const config = {
    server: process.env.DB_HOST,        // "sqlserver" in Docker
    port: parseInt(process.env.DB_PORT),
    user: process.env.DB_USER,
    password: process.env.DB_PASSWORD,
    database: process.env.DB_NAME,
    options: {
      encrypt: false,                   // IMPORTANTE: false per container locale
      trustServerCertificate: true
    }
  };

Se già usi process.env, controlla solo che i nomi delle variabili
corrispondano a quelli nel docker-compose.yml (DB_HOST, DB_PORT, ecc.)


## PASSO 4 — Controlla le chiamate API nel frontend Vue

Le chiamate dal frontend al backend devono usare un path relativo /api/
e NON localhost:3000 — nginx farà da intermediario.

  // ❌ PRIMA (non funziona in Docker)
  axios.get('http://localhost:3000/utenti')

  // ✅ DOPO (funziona in Docker e in locale con proxy)
  axios.get('/api/utenti')

Se usi un file di configurazione (es. .env.local in Vue con VITE_API_URL),
impostalo a /api in produzione.


## PASSO 5 — Crea il file .env

Copia .env.example in .env e compila:

  DB_USER=sa
  DB_PASSWORD=TuaPassword123!
  DB_NAME=GestionaleManutenzioni
  OPENAI_API_KEY=sk-...

⚠️ Aggiungi .env al .gitignore — non deve mai andare su GitHub!


## PASSO 6 — Prima build e avvio

Apri il terminale nella root del progetto ed esegui:

  # Build e avvio di tutti i container
  docker compose up --build -d

  # Controlla che tutto sia partito
  docker compose ps

  # Vedi i log in tempo reale
  docker compose logs -f

  # Solo i log del backend
  docker compose logs -f backend


## PASSO 7 — Verifica

  Frontend →  http://localhost
  Backend  →  http://localhost:3000
  DB       →  connettiti con SSMS su localhost,1433  utente: sa


## COMANDI UTILI OGNI GIORNO

  # Avvia tutto (senza rebuild)
  docker compose up -d

  # Ferma tutto
  docker compose down

  # Ricostruisci dopo modifiche al codice
  docker compose up --build -d

  # Apri una shell nel container backend
  docker exec -it gestionale-manutenzioni-backend-1 sh

  # Vedi tutti i container attivi
  docker ps


## PROBLEMI COMUNI

PROBLEMA: Il backend non si connette al DB
SOLUZIONE: SQL Server impiega 20-30 secondi ad avviarsi. Il healthcheck
nel docker-compose aspetta automaticamente, ma se vedi errori di connessione
aspetta un minuto e i container si riavvieranno da soli (restart: unless-stopped)

PROBLEMA: "Cannot find module" nel backend
SOLUZIONE: Hai dipendenze installate globalmente. Aggiungile al package.json
con npm install <pacchetto> --save

PROBLEMA: La porta 80 è già occupata
SOLUZIONE: Cambia nel docker-compose.yml:  "80:80"  →  "8080:80"
e accedi su http://localhost:8080

PROBLEMA: La porta 1433 è già occupata (SQL Server locale attivo)
SOLUZIONE: Ferma il servizio SQL Server locale di Windows oppure
cambia la porta esposta: "1434:1433" e connettiti su localhost,1434
